Purpose
=======
This is an existing V2 production-style Africa-scale geospatial intelligence platform.
It is not a new project. It combines:
- FastAPI backend
- Leaflet frontend
- Earth Engine analysis
- STAC fallback/discovery
- GeoTIFF/COG export plumbing
- AOI polygon/quadrilateral analysis
- Point inspection
- Water, climate, glacier, and agriculture/food-security indicators

Main product domains:
- Water intelligence: flood, turbidity/sediment, chlorophyll/algal bloom, water quality proxy, historical water extent.
- Climate/dryness: soil moisture, drought indices, glacier/snow retreat.
- Agriculture/food security: cropland extent, cropland conversion, crop phenology, FEWS NET food-security class.

Scientific Dataset Mapping
==========================
Water/climate layers:
- Flood extent mapping:
  Source: Sentinel-1 SAR only.
  Methods: VV/VH thresholding and change/wetness proxies.
  Important: Do not use Sentinel-2 for operational flood detection.

- Sediment plumes / turbidity:
  Source: Sentinel-2 SR Harmonized.
  Methods: NDWI/MNDWI water masking, NDTI/red-band ratios.
  Important: proxy only, not calibrated NTU.

- Algal blooms / chlorophyll-a:
  Source: Sentinel-3 OLCI.
  Methods: NDCI-style band ratio using OLCI red/red-edge radiance bands.
  Important: proxy only unless regionally calibrated.

- Water quality proxy:
  Source: derived from Sentinel-2 turbidity + Sentinel-3 chlorophyll proxies.
  Important: not direct chemistry or drinking-water safety.

- Soil moisture:
  Source: SMAP L4 preferred; Sentinel-1 SAR proxy fallback.
  Important: SAR moisture proxy requires calibration for operational use.

- Drought indices:
  Source: CHIRPS + TerraClimate.
  Methods: SPI/SPEI/PDSI-like proxies.
  Important: keep as climate index/proxy, not crop-yield score.

- Glacial retreat:
  Source: Sentinel-2 + Landsat.
  Methods: NDSI/snow/ice area proxy and temporal retreat.
  Important: only meaningful in glaciated or persistent snow regions.

- Historical water:
  Source: JRC Global Surface Water.
  Methods: occurrence, seasonality, recurrence, transition, yearly/discrete history.

Agriculture layers:
- Cropland extent:
  Source: GOOGLE/DYNAMICWORLD/V1.
  Method: crops probability threshold/frequency/area summary over AOI.
  Chart: yearly line/area chart, km2.

- Cropland conversion:
  Source: Dynamic World temporal comparison.
  Method: compare year N vs N-1; gain/loss/net separately.
  Chart: gain/loss bars.

- Crop phenology:
  Source: Sentinel-2 SR Harmonized.
  Method: SCL cloud-masked monthly NDVI/EVI composites.
  Chart: monthly seasonal line for latest valid year.

- Food security:
  Source: FEWS NET.
  Method: centroid-based categorical IPC phase lookup.
  Chart: categorical risk blocks.
  Important: never interpolate, never convert to continuous score.

Known Bugs / Risks Remaining
============================
1. Agriculture service contains unreachable old code after return.
   Priority: medium.
   Impact: not runtime-breaking, but confusing and should be deleted.

2. Long agriculture ranges or large AOIs can still cause EE 429 / "Too many concurrent aggregations".
   Priority: high for production.
   Mitigation now: shorter default range, sequential EE calls, graceful partial state.
   Future fix: reduce server-side aggregations further, tile large AOIs, add background jobs, or generate exported tables/assets asynchronously.

3. FEWS NET lookup is centroid-based and often unavailable.
   Priority: medium.
   Future fix: cache official FEWS NET geometries, spatially intersect AOI with zones, area-weight categorical classes.

4. Water/glacier historic Landsat collections need careful re-verification.
   Priority: medium.
   Risk: mixed Landsat sensors can produce non-homogeneous ImageCollection errors.

5. Derived image timestamps must be handled carefully.
   Priority: medium.
   Risk: calling image.date() on composites without system:time_start can fail.

6. STAC queries can time out on Planetary Computer.
   Priority: medium.
   Current behavior: logs warning and should fallback/unavailable.
   Future fix: narrow bbox/time windows, request limit=1 where possible, cache collection searches, add provider timeouts.

7. Static files can be cached by browser.
   Priority: low.
   Mitigation: hard refresh.

8. Production scalability is not fully solved.
   Priority: high for deployment.
   Future fix: job queue, async task status endpoint, persistent Redis cache, object storage for GeoTIFF/COG outputs.
